## 版本边界

本 Qoder 离线快照与 PR #18 的 Issue #4 Agent Graph 实现配套，PR #19 必须在
PR #18 之后合并。`apps/agent/tests/test_counsel_graph.py` 由 PR #18 引入；若只检出
PR #19 相对旧 `main` 的分支，该文件尚不存在。

仓库当前没有配置覆盖率采集或最低覆盖率阈值。本文不声称 90% 覆盖率，也不声称
CI 会生成覆盖率报告。

## 测试入口

### Web

在仓库根执行：

```bash
pnpm lint
pnpm typecheck
pnpm test:ci
pnpm build
```

Vitest 配置位于 `apps/web/vitest.config.ts`。现有测试覆盖页面错误状态、Composer、
Artifact 和取消流式响应等行为。

### Agent

在 `apps/agent` 执行：

```bash
uv sync --dev
uv run pytest
```

合并 PR #19 后，也可以在仓库根执行：

```bash
pnpm test:agent
pnpm test:all
```

`test_graph.py` 覆盖 Graph 编译、模型响应、消息追加和设置校验。
`test_counsel_graph.py` 覆盖五种模式、Run Context 优先级、自动模式判断、澄清与
调研延后、阶段状态和降级路径。

## CI

`.github/workflows/ci.yml` 分别运行 Web 与 Agent 检查。根 `package.json` 的
`test:all` 是本地聚合入口，不替代 lint、类型检查或生产构建。

## 编写原则

- LLM、网络和持久化依赖使用 fake、stub 或 monkeypatch，避免真实外部调用。
- 路由测试断言模式、阶段序列和 recommendation kind，不依赖完整自然语言文案。
- 每个异常路径同时断言用户可读消息和结构化错误状态。
- 流式或 Thread 行为变更需补充集成测试；跨 Web/Agent 协议变更还需运行 smoke。

## 常见问题

- `ModuleNotFoundError`：先在 `apps/agent` 执行 `uv sync --dev`。
- Web 测试缺 DOM API：确认 Vitest 使用项目 setup 文件。
- smoke 无法连接：确认 Agent 服务已启动，并检查 `http://localhost:2024/ok`。
- `.pytest_cache` 权限警告：不影响测试断言，但应修复目录权限以恢复缓存。
