# 刘亚楼参谋台（LYL）技术与交互规格说明 SPEC

> 文档版本：V1.0  
> 适用范围：MVP / 第一版  
> 前端基线：`langchain-ai/agent-chat-ui`  
> 后端基线：LangGraph 单主 Agent + 条件化工具与轻量研究分支  
> 更新时间：2026-07-28

---

## 0. 规格目标

本规格用于指导第一版的前端改造、后端 Agent 实现、数据建模、接口定义、评测与发布验收。

设计原则：

1. 先保证参谋能力可用，不追求复杂 UI；
2. 复用 Agent Chat UI 的 Thread、Streaming、Interrupt、File Upload 和 Artifact；
3. 第一版只实现一个长期主 Agent，不建设固定多 Agent 军团；
4. Workflow 只用于复杂调研的内部条件分支，不建设 Workflow 编辑器；
5. Skill 是主 Agent 可调用的行为协议，不作为独立产品；
6. 记忆必须结构化、可追溯、可修正；
7. 不展示私有思维链，只展示任务阶段、证据和结论。

## 2. 技术选型

## 2.1 前端

- Next.js 15+
- React 19+
- TypeScript
- Tailwind CSS
- Radix UI
- LangGraph SDK
- 复用 Agent Chat UI 的 Stream Provider、Thread History、Message Renderer、File Upload、Interrupt 和 Artifact

第一版不主动升级依赖大版本，先锁定 fork 时的可运行版本。

## 2.2 后端

推荐 Python：

- Python 3.12+
- LangGraph
- LangChain Core
- FastAPI（仅在需要自定义业务 API 时）
- Pydantic
- PostgreSQL；本地开发允许 SQLite
- pgvector 或独立向量库为可选项，不作为 MVP 强依赖

## 2.3 模型

模型接口必须可配置，不在代码中绑定单一供应商。

配置维度：

- 主推理模型；
- 快速分类模型；
- 调研模型；
- 摘要模型；
- Embedding 模型。

MVP 可先复用同一个高质量模型，待成本与稳定性验证后再拆分。

# 第二部分：Agent Chat UI 改造规格

## 3. 保留能力

直接保留：

- Thread 创建与切换；
- Thread History；
- 流式消息；
- 停止运行；
- 重新生成；
- 文件上传；
- Markdown 和代码渲染；
- Tool Call 展示；
- Error Toast；
- Interrupt；
- Artifact 右侧面板；
- Resumable Stream；
- 隐藏内部消息机制。

---

## 4. 移除或隐藏

### 4.1 配置页

生产环境不允许用户填写：

- Deployment URL；
- Assistant ID；
- LangSmith API Key。

改为服务端环境变量和 API Proxy。

开发环境可保留隐藏设置页，仅管理员可访问。

### 4.2 品牌元素

替换：

- LangGraph Logo；
- “Agent Chat”；
- GitHub 跳转按钮；
- 默认欢迎文案。

产品名称统一为：

- 中文：刘亚楼参谋台
- 简称：LYL
- 内部 Agent ID：`lyl_counsel_agent`

## 6. 欢迎区组件

新增 `CounselWelcome`：

```typescript
interface CounselWelcomeProps {
  onSelectMode(mode: CounselMode): void;
}
```

展示四个入口：

```typescript
type CounselMode =
  | "ask"
  | "decide"
  | "research"
  | "diagnose"
  | "discuss";
```

卡片文案：

- `ask`：下一步做什么
- `decide`：帮我做决定
- `research`：调研后判断
- `diagnose`：诊断历史思维

点击后不立即发送空消息，而是：

1. 设置当前 Draft Mode；
2. 修改输入框 Placeholder；
3. 可插入模式提示语；
4. 用户提交后将 mode 放入 Run Context。

---

## 7. Composer 改造

输入数据：

```typescript
interface CounselInput {
  text: string;
  files: UploadedFile[];
  mode: CounselMode;
  scope?: "local" | "global";
}
```

输入框顶部显示当前模式 Chip，可切换或清除。

Placeholder：

- ask：`描述你现在卡住的事情，或直接问“下一步做什么”`
- decide：`描述你需要拍板的选择`
- research：`描述需要调研并形成判断的问题`
- diagnose：`描述要诊断的时间范围或主题`
- discuss：`和刘亚楼讨论……`

## 8. 消息类型

继续使用 LangGraph `messages`，自定义结构通过两种机制表达：

1. Chat 中的轻量 UI Message；
2. Artifact 中的完整结构化对象。

定义：

```typescript
type CounselUIType =
  | "stage_progress"
  | "context_summary"
  | "clarification_request"
  | "research_plan"
  | "counsel_summary"
  | "memory_proposal"
  | "feedback_request";
```

禁止通过普通 Markdown 模拟所有交互。需要用户点击或系统读取的内容必须结构化。

## 9. 参谋进度组件

新增 `CounselProgress`：

```typescript
interface CounselStage {
  id: string;
  title: string;
  status: "pending" | "running" | "completed" | "blocked" | "skipped";
  summary?: string;
}
```

默认阶段按模式生成，不固定显示全部节点。

### ask

- 恢复上下文；
- 判断当前阶段；
- 识别主要矛盾；
- 形成下一步。

### decide

- 重构决策；
- 核对目标与约束；
- 补齐关键事实；
- 反方审查；
- 形成建议。

### research

- 快速摸底；
- 规划关键未知；
- 定向调研；
- 证据审查；
- 更新判断。

### diagnose

- 确认数据范围；
- 检索历史；
- 识别模式；
- 证据核对；
- 形成诊断。

进度仅展示工作状态，不展示模型私有推理过程。

## 10. Interrupt 组件

LangGraph Interrupt 用于需要用户输入后恢复的场景。

定义三种 Interrupt：

```typescript
type CounselInterrupt =
  | ScopeClarificationInterrupt
  | ValueTradeoffInterrupt
  | ResearchApprovalInterrupt;
```

### 10.1 范围确认

```typescript
interface ScopeClarificationInterrupt {
  type: "scope_clarification";
  question: string;
  options: Array<{
    id: string;
    label: string;
    description?: string;
  }>;
  recommended?: string;
}
```

### 10.2 价值取舍

```typescript
interface ValueTradeoffInterrupt {
  type: "value_tradeoff";
  question: string;
  why_needed: string;
  options: Array<{
    id: string;
    label: string;
    cost: string;
  }>;
  recommended?: string;
}
```

### 10.3 调研批准

```typescript
interface ResearchApprovalInterrupt {
  type: "research_approval";
  key_unknowns: string[];
  proposed_angles: string[];
  stop_conditions: string[];
  actions: ("approve" | "modify" | "report_now")[];
}
```

规则：

- 单次会商默认最多主动 Interrupt 2 次；
- 每次只询问一个会实质改变结果的维度；
- 能从历史或外部事实获得的信息不得询问用户；
- 用户可选择“按现有信息直接汇报”。

## 11. Artifact 改造

定义 `CounselArtifact`：

```typescript
interface CounselArtifact {
  artifact_type: "next_action" | "decision" | "research" | "diagnosis";
  title: string;
  version: number;
  status: "draft" | "final" | "superseded";
  tabs: {
    counsel: CounselCard;
    evidence?: EvidenceView;
    history?: HistoryBasisView;
    process?: ResearchProcessView;
  };
}
```

右侧 Tab：

- 参谋结论；
- 关键证据；
- 历史依据；
- 调研过程。

Artifact 更新规则：

- 允许流式更新；
- 最终建议生成后 version +1；
- 新建议不得覆盖旧建议，旧版本标记 `superseded`；
- 用户可查看版本变化和改判原因。
