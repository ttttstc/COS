# 第四部分：信息架构与交互

## 10. 第一版页面结构

第一版以 Agent Chat UI 为基础，采用三层结构。

### 10.1 左侧：历史会商

保留 Thread History，改名为“历史会商”。

每条会商显示：

- 自动生成标题；
- 类型：下一步 / 决策 / 调研 / 诊断 / 普通会商；
- 更新时间；
- 当前状态；
- 是否有待用户裁决；
- 是否已形成参谋建议。

状态最小化为：

- 会商中；
- 调研中；
- 待用户裁决；
- 已形成建议；
- 已归档。

### 10.2 中间：参谋对话

保留：

- 流式消息；
- Markdown；
- 文件上传；
- 工具调用状态；
- 停止；
- 重新生成；
- Interrupt；
- 新建会话。

新增：

- 四个快捷入口；
- 结构化进度卡；
- 关键问题裁决卡；
- 参谋建议摘要；
- 采纳、不同意、补充调研、记录结果操作。

### 10.3 右侧：参谋材料 Artifact

Artifact 面板改造成四个 Tab：

1. **参谋结论**
2. **关键证据**
3. **历史依据**
4. **调研过程**

默认只在产生结构化材料时打开，不强制常驻。

## 11. 首屏设计

### 11.1 欢迎区

主标题：

> 今天需要参谋什么？

快捷入口：

- 下一步做什么；
- 帮我做决定；
- 调研后判断；
- 诊断历史思维。

输入框仍支持自由输入。

### 11.2 第一版不建设独立 Dashboard

第一版直接进入会商界面，不增加“今日待办、战略看板、长期任务”等页面，避免产品过重。

## 12. 关键交互流程

## 12.1 `ask-lyl` 流程

1. 用户点击“下一步做什么”或自然语言触发；
2. 系统判断是局部问题还是全局优先级；
3. 如范围无法可靠判断，只询问一个必要问题；
4. 检索相关当前目标、事项、近期决定和历史模式；
5. 判断用户当前阶段和主要矛盾；
6. 判断是否需要外部调研；
7. 形成唯一主行动；
8. 展示参谋判断卡；
9. 用户选择采纳、不同意、补充信息或要求调研；
10. 系统保存反馈。

## 12.2 `decide-lyl` 流程

1. 用户提出选项或决策问题；
2. 系统重构真正的决策命题；
3. 恢复目标、约束和历史相关记录；
4. 区分事实、假设、价值与未知；
5. 信息不足时提出调研计划；
6. 必要时通过 Interrupt 请求一个关键裁决；
7. 形成方案比较；
8. 执行反方审查；
9. 输出明确预决策；
10. 用户拍板或要求重判；
11. 保存最终选择和理由。

## 12.3 `research-lyl` 流程

1. 定义研究服务的决策；
2. 识别 1–5 个关键未知；
3. 显示研究计划和预算；
4. 用户可批准、修改或按现有信息直接汇报；
5. 执行搜索、文件分析或独立研究分支；
6. 对证据进行来源、时效和相关性评级；
7. 解决冲突或明确保留不确定性；
8. 更新原有判断；
9. 形成调研结论和参谋建议。

## 12.4 `diagnose-lyl` 流程

1. 用户指定时间范围或主题；
2. 系统展示将使用的数据范围；
3. 用户确认；
4. 检索历史聊天、记忆和决策；
5. 聚类反复出现的问题与行为；
6. 为每个模式抽取可追溯证据；
7. 区分优势、风险模式和临时状态；
8. 输出诊断报告；
9. 用户确认、否认或修正；
10. 仅经确认的模式进入长期记忆。

# 第五部分：记忆与个性化

## 13. 记忆模型

第一版只维护四类结构化记忆。

### 13.1 当前目标

示例：

- 当前正在验证个人参谋 Agent 是否值得开发；
- 本阶段优先获得真实用户反馈；
- 当前工作重点是流水线智能化规划。

字段：

- 内容；
- 来源；
- 创建时间；
- 最后确认时间；
- 可信度；
- 状态：候选 / 已确认 / 已失效；
- 适用范围：工作 / 生活 / 项目。

### 13.2 当前事项

记录用户正在考虑或推进的事项，但不作为任务管理系统。

字段：

- 事项名称；
- 当前阶段；
- 最近变化；
- 当前阻塞；
- 关联目标；
- 更新时间；
- 状态。

### 13.3 重要决策

记录：

- 决策命题；
- 当时背景；
- 关键事实；
- 关键假设；
- 参谋建议；
- 用户选择；
- 选择理由；
- 置信度；
- 改判条件；
- 后续结果；
- 复盘状态。

### 13.4 思维模式

记录经过证据支持和用户确认的模式。

字段：

- 模式描述；
- 类型：优势 / 风险 / 待观察；
- 支持证据；
- 反例；
- 适用场景；
- 可信度；
- 用户是否确认；
- 最近更新时间。

---

## 14. 记忆原则

- 聊天历史不等于长期记忆；
- 随口表达不得直接写入高置信度记忆；
- 关键记忆必须保存来源和时间；
- 过时信息应降权或失效；
- 用户可查看、编辑、删除；
- 诊断结论未经用户确认不得作为稳定人格事实；
- 同一主题存在冲突时必须显式呈现；
- 高风险隐私默认不进入长期记忆；
- 第一版不做复杂知识图谱。

# 第六部分：差异化与护城河

## 15. 相对通用 Agent 的核心差异

### 15.1 Personal State Model

不只知道用户的偏好，而是理解用户当前的目标、阶段、投入、阻塞和现实约束。

### 15.2 Decision Memory

保存决策的因果链，而不是只保存聊天文本。

### 15.3 Personal Doctrine

从历史结果中形成适合用户的决策规则，例如：

- 新产品先验证真实场景，再设计完整平台；
- 可逆决策优先快速试验；
- 没有新增证据时停止继续调研；
- 同时主攻方向不超过两个。

第一版只允许用户确认后的规则生效。

### 15.4 Next-Best-Action

`ask-lyl` 不是待办排序，而是基于主要矛盾和最大不确定性选择一个当前最有价值的行动。

### 15.5 Calibrated Counsel

系统明确表达置信度、适用边界和改判条件，不对所有领域表现相同自信。

### 15.6 Historical Pattern Diagnosis

系统能指出：

- 用户是否重复讨论同类问题；
- 是否长期停在研究阶段；
- 是否频繁扩大范围；
- 哪些建议被采纳以及效果如何。

差异化不能只依赖 Prompt，必须依赖结构化个人状态、决策记录和结果反馈。
