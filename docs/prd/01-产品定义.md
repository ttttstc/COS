## 0. 文档摘要

刘亚楼参谋台是一款由用户主动触发的个人战略参谋 Agent。它面向用户在工作和生活中遇到的三类高价值问题：

1. **不知道下一步做什么**；
2. **面对多个选项难以决断**；
3. **希望基于历史聊天和记忆诊断自己的思维模式**。

产品不是通用聊天机器人，也不是任务执行平台。它的核心职责是：理解用户的长期目标与现实约束，重构问题，识别当前主要矛盾，按需调研关键未知，形成明确、可解释、可反驳的参谋建议，并通过用户反馈持续校准。

第一版采用 LangChain Agent Chat UI 作为交互底座，保留会话、流式消息、文件上传、工具调用、Interrupt 和 Artifact 等既有能力，只做满足参谋场景所需的最小改造。第一版重点验证参谋能力，不重点打磨视觉设计。

# 第一部分：产品定义

## 1. 产品背景

通用大模型已经能够回答问题、列出优缺点、生成分析报告，但在真实决策中仍存在四个结构性缺陷：

### 1.1 只理解当前问题，不理解当前的人

同一个建议对不同用户可能完全不同。通用 Agent 通常缺少稳定的个人目标、当前阶段、家庭与工作约束、历史选择以及长期行为模式。

### 1.2 容易提供“全面信息”，但不承担明确判断

通用 Agent 常输出多个方案和利弊，最后把选择重新交还给用户。对于已经犹豫不决的用户，这会增加认知负担。

### 1.3 缺少时间连续性

它通常不知道用户已经围绕某个方向讨论多久、是否反复改变范围、上次做了什么决定、建议是否执行以及结果如何。

### 1.4 缺少可校准的决策记录

没有结构化保存“当时已知什么、建议什么、用户选择什么、后来发生什么”，就无法判断建议质量，也无法形成用户自己的决策方法。

刘亚楼参谋台试图解决的不是“回答得更像专家”，而是建立一个长期服务于具体用户的参谋关系。

---

## 2. 产品愿景

> 当用户不知道该做什么、无法决定或需要审视自己的思维时，刘亚楼参谋台能够基于用户的真实处境与长期目标，找出主要矛盾，补齐必要信息，并给出最值得采取的行动或选择。

长期愿景是帮助用户逐步形成更稳定、更敏锐、更独立的思考和决策能力。

第一版不主动进行日常思维训练。认知诊断由用户主动触发，系统基于历史聊天、记忆和决策记录进行阶段性分析。

---

## 3. 产品定位

### 3.1 一句话定位

**一个长期理解用户、在关键时刻给出明确主张的个人战略参谋 Agent。**

### 3.2 产品品类

- Personal Strategic Counsel
- Personal Decision Agent
- 个人战略参谋台

### 3.3 角色定位

刘亚楼是参谋长角色原型，不是历史人物模拟器。产品不机械模仿人物语言，也不以权威压制用户。

它拥有：

- 问题重构权；
- 信息调研权；
- 方案分析权；
- 反方审查权；
- 明确建议权；
- 请求用户裁决权；
- 建议记录与复盘权。

它不拥有：

- 替用户作出不可逆人生决定的权力；
- 未经授权的对外执行权；
- 对医疗、法律、投资等高风险问题作最终结论的权力；
- 操纵、羞辱或强迫用户的权力。

最终拍板和责任始终属于用户。

## 4. 产品目标与非目标

## 4.1 第一版目标

第一版必须验证以下核心假设：

1. 基于长期上下文的 Agent 能否比通用 Agent 更准确地识别用户真正的问题；
2. 系统能否在信息不全时识别“最值得补齐的关键未知”，而不是无限调研；
3. 系统能否给出一个明确、可解释、可执行的下一步或决策建议；
4. 历史聊天与决策记录能否使建议产生明显的个性化差异；
5. 用户是否愿意采纳、反驳、纠正并持续使用这个参谋。

## 4.2 第一版非目标

第一版不建设：

- 项目管理系统；
- 任务执行平台；
- 多 Agent 可视化编排器；
- Workflow 编辑器；
- 自动操作邮件、日历、代码仓或外部系统；
- 主动监控用户日常生活并持续干预；
- 自动推送思维训练；
- 面向企业的多人协作和权限体系；
- 模型市场、Agent 市场、Skill 市场；
- 完整知识管理或第二大脑平台。

## 5. 产品原则

### 5.1 用户负责价值取舍，Agent 负责事实准备

能通过历史、文件或公开信息调查的问题，系统应先自行调查。只有会实质改变方向、约束、风险边界或最终选择的问题才询问用户。

### 5.2 先判断是否值得分析

低成本、可逆的选择优先建议快速行动，不启动重型调研。

### 5.3 结论先行，证据按需展开

用户首先看到建议、主要矛盾和下一步，而不是长篇过程日志。

### 5.4 默认只给一个主建议

可以提供备选，但必须明确首选方案。不能以“各有利弊”逃避判断。

### 5.5 明确不做什么

好的下一步建议必须同时说明哪些事项应该暂缓、冻结或停止。

### 5.6 区分事实、假设、价值与情绪

系统不能把用户表达的担忧直接当事实，也不能把模型推测伪装成确定结论。

### 5.7 允许用户反驳并修改上下文

长期记忆必须可见、可纠正、可删除。用户不同意时，系统应识别是新事实、价值排序不同，还是对困难行动的回避，但不能剥夺用户决定权。

### 5.8 不迷信复杂框架

第一性原理、主要矛盾、奥卡姆剃刀等是工具，不是固定模板。一个问题能用三句话说清，就不应套十个理论。
