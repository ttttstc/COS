# 第七部分：功能需求

## 16. 功能需求清单

### FR-001 会商创建

用户可以新建普通会商，或通过四个快捷入口创建指定模式会商。

### FR-002 会商历史

系统保存会商标题、类型、状态、更新时间和消息历史。

### FR-003 流式回答

系统支持 Agent 内容流式输出，用户可停止当前运行。

### FR-004 文件输入

用户可上传文本、Markdown、PDF、图片或常见文档作为当前会商上下文。第一版可限制文件大小和格式。

### FR-005 模式识别

系统可根据自然语言识别 `ask / decide / research / diagnose / discuss`，但用户可手动切换。

### FR-006 上下文恢复

系统检索与本次问题相关的目标、事项、决策和已确认模式。

### FR-007 上下文可见

用户可以查看本次判断使用了哪些历史上下文，并移除不相关项。

### FR-008 必要问题 Interrupt

当缺失信息会实质改变判断时，Agent 可暂停并请求用户裁决。

### FR-009 调研计划

需要调研时，系统展示关键未知、研究方向、预计来源类型和停止条件。

### FR-010 调研进度

系统以结构化步骤展示调研进度，不展示私有思维链。

### FR-011 证据记录

每条关键证据保存来源、日期、摘要、相关性、可信度和支持/反对关系。

### FR-012 参谋判断卡

系统支持结构化渲染下一步建议、决策建议和诊断结果。

### FR-013 右侧 Artifact

系统可将参谋结论、证据、历史依据和调研过程展示在右侧面板。

### FR-014 用户反馈

用户可标记：

- 采纳；
- 不同意；
- 需要补充调研；
- 已完成；
- 判断错误；
- 稍后复盘。

### FR-015 决策记录

重要建议可保存为决策记录，普通聊天默认不生成决策记录。

### FR-016 记忆管理

用户可查看、编辑、确认、失效和删除记忆。

### FR-017 历史诊断

用户可选择时间范围和主题，主动发起历史思维诊断。

### FR-018 诊断证据

每个诊断结论必须关联历史消息或决策记录。

### FR-019 置信度与改判条件

正式建议必须包含置信度等级和触发改判的条件。

### FR-020 高风险领域限制

医疗、法律、投资和人身安全问题必须显示能力边界，并优先引导用户获得专业帮助。

# 第九部分：指标与验收

## 20. 北极星指标

**被用户认为“比通用 Agent 更懂我、更能推动决定”的有效参谋会商比例。**

第一版通过会商后评分衡量：

- 是否抓住真正问题；
- 是否提供了有价值的新信息；
- 是否给出了明确主张；
- 是否帮助用户采取行动或做出决定。

---

## 21. 核心产品指标

### 21.1 建议有效性

- 参谋建议“有帮助”比例；
- 用户采纳或部分采纳比例；
- 用户主动要求继续使用比例；
- 建议完成后结果反馈率。

### 21.2 判断质量

- 用户认为主要矛盾识别准确的比例；
- 调研后建议发生合理更新的比例；
- 关键事实引用正确率；
- 无依据或错误记忆引用率。

### 21.3 个性化价值

- 历史上下文对建议产生实质影响的会商比例；
- 用户确认“该建议不是通用答案”的比例；
- 被用户纠正的长期记忆比例；
- 已确认个人决策原则数量。

### 21.4 效率

- 普通参谋首个有效建议时间；
- 深度调研完成时间；
- 不必要澄清问题数量；
- 单次会商平均工具调用量；
- 因过度调研被用户停止的比例。

---

## 22. MVP 发布验收标准

满足以下条件才能发布第一版：

1. 四个核心入口均可运行；
2. 连续会话、历史 Thread、流式消息和停止能力稳定；
3. 支持至少一种文件上传和历史聊天输入；
4. 可从结构化记忆检索相关上下文；
5. 可展示并修正本次使用的历史依据；
6. 可通过 Interrupt 请求用户裁决并恢复运行；
7. 可在右侧 Artifact 展示参谋卡和证据；
8. 正式建议包含主要矛盾、明确主张、置信度和改判条件；
9. 用户反馈可写入决策记录；
10. 历史诊断结果包含可追溯证据；
11. 高风险领域具备明确限制；
12. 至少完成 30 个真实问题的人工评测；
13. 与同模型通用聊天基线相比，参谋台在“个性化、明确性、可执行性”三个维度中至少两个显著更优。

# 第十一部分：风险与应对

## 26. 产品风险

### 26.1 建议过于自信

应对：

- 强制显示置信度和未知；
- 正式决策必须有改判条件；
- 高风险领域降级为信息整理和专业求助建议。

### 26.2 长期记忆产生错误偏见

应对：

- 记忆附来源、时间和置信度；
- 用户可纠正；
- 过时记忆自动降权；
- 诊断结论需用户确认。

### 26.3 产品变成说教工具

应对：

- 认知诊断仅主动触发；
- 普通会商不主动训诫；
- 结论聚焦当前问题；
- 默认提供行动，不进行人格评价。

### 26.4 过度调研加剧拖延

应对：

- 调研前定义关键未知和停止条件；
- 默认限制研究分支；
- 信息增益不足时停止；
- 可逆问题优先试验。

### 26.5 与通用 Agent 差异不明显

应对：

- 强制使用个人状态和历史决策；
- 显示本次历史依据；
- 建立建议结果反馈；
- 用 A/B Eval 与通用 Agent 对比。

### 26.6 角色名带来权威依赖

应对：

- 明确参谋不是统帅；
- 用户拥有最终决定权；
- 允许反驳；
- 禁止使用压迫、羞辱和操纵语言。

# 附录 B：技术基线说明

第一版基于 `langchain-ai/agent-chat-ui`：

- Next.js 应用；
- 接入包含 `messages` 状态的 LangGraph Server；
- 支持 Thread 和流式消息；
- 支持文件内容块；
- 支持可恢复运行和子图流；
- 支持 Interrupt；
- 支持右侧 Artifact；
- MIT License。

产品只复用交互底座，不将 LangChain 或 LangGraph 作为产品差异化卖点。
